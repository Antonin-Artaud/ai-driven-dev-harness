# Memory

| Tier | Rule | When not, pitfalls | Version | Source |
|---|---|---|---|---|
| A | Avoid boxing value types in hot code: boxing allocates and constructs a new object; unboxing is also costly. | Unboxing `null` throws `NullReferenceException`, the wrong type `InvalidCastException`. | not stated | https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing |
| A | Avoid many short-lived large objects (85,000 bytes and more go to the large object heap); cache or pool large buffers. | — | not stated | https://learn.microsoft.com/en-us/aspnet/core/fundamentals/best-practices |
| B | `Span<T>` / `ReadOnlySpan<T>` for synchronous slicing and parsing without copies; take `Span<T>` rather than `Memory<T>` as parameter of a synchronous API; read-only views when the buffer must not change. | A span lives on the stack only: not a class field, not across `await`; a span cannot become a `Memory<T>`. | not stated | https://learn.microsoft.com/en-us/dotnet/standard/memory-and-spans/memory-t-usage-guidelines |
| B | `Memory<T>` / `ReadOnlyMemory<T>` when the buffer crosses `await` or is stored on the heap. | After a method taking `Memory<T>` returns (or its `Task` completes), the callee must not use it any more. | not stated | https://learn.microsoft.com/en-us/dotnet/standard/memory-and-spans/memory-t-usage-guidelines |
| B | `IMemoryOwner<T>` from `MemoryPool<T>.Shared.Rent()`: the owner disposes it, or transfers ownership, never both; a parameter of type `IMemoryOwner<T>` takes ownership. | Use after dispose is a bug. | not stated | https://learn.microsoft.com/en-us/dotnet/standard/memory-and-spans/memory-t-usage-guidelines |
| B | `stackalloc` for small temporary buffers, guarded by a conservative constant limit with a heap fallback: `len <= MaxStackLimit ? stackalloc byte[len] : new byte[len]`. | Never in a loop (allocate once outside); the memory is not initialized; too much stack throws `StackOverflowException`; unmanaged `T` only; reject negative lengths. | not stated | https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/stackalloc |
| B | `ArrayPool<T>.Shared.Rent`/`Return` for buffers created and destroyed frequently (heap fallback of `stackalloc` included); return in a `finally`. | `Rent` returns an array *at least* the requested length: use the requested length, not `array.Length`; return to the same pool; the pool is thread-safe. | not stated | https://learn.microsoft.com/en-us/dotnet/api/system.buffers.arraypool-1 |
| B | `readonly struct` or `readonly` members for small value types; `in` / `ref readonly` parameters to avoid copies of larger structs (prefer `ref readonly` when the method captures or returns the reference). | Copying is negligible for types of three words or less; spans contain a ref field and cannot leave their safe context. | not stated | https://learn.microsoft.com/en-us/dotnet/csharp/advanced-topics/performance/ |
| B | `ref struct` locals and spans in async methods and iterators, as long as they are not used across `await` or `yield return`. | Not before C# 13. | C# 13 (.NET 9) | https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-13 |
| B | `ObjectPool<T>` (`Microsoft.Extensions.ObjectPool`) only for objects expensive to create or limited, after measuring with realistic scenarios. | Cheap objects are slower to get from a pool than to allocate; pooled objects stay alive until the pool is disposed. | not stated | https://learn.microsoft.com/en-us/aspnet/core/performance/objectpool |
