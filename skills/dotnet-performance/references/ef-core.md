# EF Core

| Tier | Rule | When not, pitfalls | Version | Source |
|---|---|---|---|---|
| A | Read queries are no-tracking: `AsNoTracking()`, or no-tracking by default for the context type with `UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking)` and `AsTracking()` on the queries that update entities. | Tracking is EF's default; with the context-level default, a write path that forgets `AsTracking()` saves nothing. | not stated | https://learn.microsoft.com/en-us/ef/core/querying/tracking |
| A | `AsNoTrackingWithIdentityResolution()` when a no-tracking result must not duplicate the same entity. | Uses a stand-alone change tracker: slower than plain no-tracking. | not stated | https://learn.microsoft.com/en-us/ef/core/querying/tracking |
| A | Project only the needed columns with `Select` (DTOs or anonymous types) instead of loading entities. | — | not stated | https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying |
| A | Filter, aggregate and limit (`Take`) in the database; watch client evaluation. | — | not stated | https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying |
| A | No N+1: eager-load with `Include` (filtered include when needed) instead of lazy loading; avoid projection queries on collections that issue one query per row. | Lazy loading is flagged as a significant performance issue. | not stated | https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying |
| A | Several collection includes: `AsSplitQuery()` (or `UseQuerySplittingBehavior(QuerySplittingBehavior.SplitQuery)`) to avoid the cartesian explosion. | No consistency across the split queries without a serializable or snapshot transaction; one round trip per collection; give a fully unique ordering with `Skip`/`Take` before EF 10. | not stated | https://learn.microsoft.com/en-us/ef/core/querying/single-split-queries |
| A | Page with keyset pagination (`Where(x => x.Id > lastId).OrderBy(x => x.Id).Take(n)`) rather than `Skip`/`Take` for page-by-page navigation. | No random page access; fully unique ordering (tiebreaker); composite index for multi-key ordering. | not stated | https://learn.microsoft.com/en-us/ef/core/querying/pagination |
| A | Set-based writes with `ExecuteUpdateAsync` / `ExecuteDeleteAsync` instead of loading and saving entities. | They bypass the change tracker (tracked instances keep stale values); each call is its own transaction and round trip; relational providers only. Version: EF Core 7 (not stated on the page; To confirm). | EF Core 7 (To confirm) | https://learn.microsoft.com/en-us/ef/core/saving/execute-insert-update-delete |
| A | Async APIs (`ToListAsync`, `SaveChangesAsync`); do not mix sync and async. Buffer with `ToListAsync` or stream with `AsAsyncEnumerable()`. | — | not stated | https://learn.microsoft.com/en-us/ef/core/performance/efficient-querying |
| A | Parameterize values (variables, not constants) so the query plan cache is reused; do not build expression trees with constants. | — | not stated | https://learn.microsoft.com/en-us/ef/core/performance/advanced-performance-topics |
| A | `AnyAsync` rather than `CountAsync` to test existence (CA1828). | — | not stated | https://github.com/dotnet/docs/blob/main/docs/fundamentals/code-analysis/quality-rules/performance-warnings.md |
| B | DbContext pooling: `AddDbContextPool<T>` (or `PooledDbContextFactory`, `AddPooledDbContextFactory`) on high-throughput services. | `OnConfiguring` runs once; contexts are reused, so no per-request state in the context; measure first. | not stated | https://learn.microsoft.com/en-us/ef/core/performance/advanced-performance-topics |
| B | Compiled queries (`EF.CompileAsyncQuery`) for hot queries. | One model per compiled query; simple scalar parameters only; measure first. | not stated | https://learn.microsoft.com/en-us/ef/core/performance/advanced-performance-topics |
| B | Compiled models (`dotnet ef dbcontext optimize`, `UseModel`) for large models and startup time. | No global query filters, lazy loading or change-tracking proxies. | not stated | https://learn.microsoft.com/en-us/ef/core/performance/advanced-performance-topics |
